Copilot Memory Hygiene

Copilot Memory saves Copilot from rediscovering your conventions, but stored memories become context too. Audit them like any other state.

MemoryGovernance~8 min

What Is Copilot Memory?

Copilot Memory helps Copilot become more effective over time by remembering facts about your repositories and your personal coding preferences.

Source: GitHub Docs, About GitHub Copilot Memory
Repository-level factsUser-level preferences
CapturesConventions, architecture decisions, build and test commands, project rulesHow you like responses, approval requirements, reusable workflows
AppliesOnly in the same repositoryAcross all your repositories
Created byUsers with write access who have Memory enabledOnly you, from your interactions
Deleted byUsers with write access, in the repository settingsYou; on Business and Enterprise, also organization or enterprise owners

Memories included in a request count toward token usage. Treat Memory as a correctness and consistency control, not a guaranteed credit reduction.

Where It Applies and Default Settings

Copilot Memory is available on all paid plans and can be used by the GitHub Copilot app, Copilot CLI, Copilot code review, Copilot cloud agent, Agentic Autofix, GitHub Mobile, and Copilot in Slack and Microsoft Teams. A memory captured by one surface can be used by another.

SurfaceDefault
Copilot CLI, interactiveOn; follows your GitHub settings. Check with /memory show; /memory off disables both types locally.
Copilot CLI, programmatic (-p)Off. Pass --enable-memory for each run.
Visual Studio CodeOff. Enable the local setting.
Copilot code review, Agentic AutofixFollow repository settings; use repository facts only, never user preferences.

On Copilot Business and Copilot Enterprise, user-level preferences stay off until an organization or enterprise owner enables the policy; you can then opt out. Repository-level facts have a separate control and are allowed unless an enterprise, organization, or repository setting restricts them.

Note: in Copilot CLI, only the root agent can store or vote on memories. Subagents can read them but not change them.

How Memories Are Checked and Retired

    Stored --> Used: citations still valid

    Stored --> Ignored: downvoted
    Stored --> Expired: no upvote in 90 days
    Ignored --> Expired
    Stored --> Deleted: you delete it
    Expired --> [*]
    Deleted --> [*]
    class Stored data
    class Used success
    class Ignored warning
    class Expired neutral
    class Deleted danger

Teal is a stored memory, green is used and reinforced, orange is no longer used, gray has expired, and red is removed by you.

  • Copilot checks a memory's citations before using it, and upvotes or downvotes it. Downvoted memories past a threshold stop being used.
  • Memories expire after 90 days without reinforcement by default. An upvote resets the timer; simply retrieving a memory does not. Owners can set repository-fact expiry between 7 and 180 days.
  • The system rejects memories that contain detected secrets, and Copilot is instructed not to store sensitive personal information or short-lived, task-specific instructions.
Important: a hidden memory is not necessarily deleted. If Copilot used a memory you don't want, delete it explicitly in the repository settings or your personal settings.

Hygiene Practices

Review on triggers

When a convention changes, a project is archived, or Copilot repeats stale advice.

Delete wrong entries now

Validation catches some outdated facts, not all of them.

Rules go in instructions

Mandatory rules belong in versioned, reviewed custom instructions. Memory holds the accumulated detail.

Be explicit about scope

Say whether a memory is for you or for everyone working in the repository.

Avoid: persisting secrets, credentials, tokens, customer or personal data, ticket numbers, temporary branch names, or “this sprint only” context in memory or instruction files.
