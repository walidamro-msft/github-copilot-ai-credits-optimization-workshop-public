Model Strategy

Use as much capability as the task requires and as little as necessary, then judge the choice by what each accepted result really cost.

ModelsRouting~15 min

Start With Automatic Routing

Defaulting to the most capable model for every task often increases token use without improving the outcome, and overusing reasoning models can even lower quality on execution-heavy tasks. Automatic routing makes the per-task choice for you.

GitHub announced Copilot Fusion as generally available on October 28, 2026. Fusion brings together Auto's model selection and Project HydraFusion's multi-model orchestration: you choose an effort level, not a specific model.

If your picker shows Copilot Fusion instead of Auto, Fusion is available on that surface. Both route along natural cache boundaries to avoid cache-related costs without quality gains.

Important: discounts and availability change often. Recheck the linked pages before you quote a figure. Fusion High and Fusion Max aren't available on every plan, and they can use more than one model per task, so a task may cost more than on Fusion Standard.

How Copilot Fusion Executes a Prompt

Fusion runs each prompt with one of three execution patterns.

Single

flowchart LR
    RQ[Request] --> P[Primary solves with tools] --> A[Answer]
    class RQ neutral
    class P azure
    class A success

Cascade

flowchart LR
    P[Primary first pass] --> J{Judge model}
    J -->|Accept| A1[Answer: primary result]
    J -->|Escalate| RP[Repair: fresh start] --> A2[Answer]
    class P azure
    class J accent
    class RP warning
    class A1,A2 success

Critique

flowchart LR
    D[Draft: primary model] --> C{Read-only critic}
    C -->|Approve| A[Answer: draft as-is]
    C -.->|Revise| RV[Revision: primary model] --> A
    class D,RV azure
    class C accent
    class A success

Adapted from GitHub's execution-pattern illustration. Blue marks the primary model, purple marks a secondary model that judges or critiques, orange marks the escalation model that restarts the task, and green marks the answer.

PatternWhat happensCost signal
SingleThe primary model solves the task with tools and answers.Like a request to one model
CascadeThe primary model makes a first pass. A secondary judge model accepts that result or escalates, and an escalation model repairs the task from a fresh start.An escalation pays for the first pass, the judge, and the repair
CritiqueThe primary model drafts. A read-only critic approves the draft as-is or asks for a revision, which the primary model makes.Adds critic calls; revision stays on the primary model and its cache

The critic can't edit files; it only describes flaws. If its feedback isn't usable, Fusion keeps the draft. The current documentation describes multiple parallel critics whose feedback is combined before revision. Fusion adds model calls only when a task warrants them, so Cascade and Critique take longer and can cost more than Single.

  • Fusion keeps the main conversation on the same model whenever possible, so it keeps benefiting from cached tokens. Assisting models receive only the context they need.
  • Fusion works separately from subagents and doesn't start them.
  • If Fusion discards a draft, file edits that draft already made are not undone automatically. Review changes before you commit.

When to Choose Manually

Model classUse for
LightweightRefactoring, formatting, documentation updates, and small, well-scoped changes you know a smaller model handles reliably
Versatile / mid-tierExecuting a plan that is already clear
Powerful / reasoningArchitecture decisions, complex debugging, system design, and planning

Reasoning effort

Configurable reasoning is available in VS Code and Copilot CLI for supported models. Higher effort produces more thinking tokens, so use the default and raise it only for genuinely hard problems. In Copilot CLI, set it with --effort (low, medium, high, xhigh, max) or from /model. Set it before the session starts; changing it mid-session invalidates the cache.

Cheaper models for subagents

Subagents run in their own context and don't inherit the main conversation, so a lighter model is often enough, and choosing one doesn't disturb the main agent's cache. In Copilot CLI, set a custom agent's model in its frontmatter or configure defaults with /subagents.

Important: in Copilot CLI, when the session model is set to Auto, subagents inherit the resolved session model and ignore their own model field. Use a specific session model when you want a subagent to run on a cheaper model.

Full Cost per Accepted Outcome

The cheapest model per attempt is not always the cheapest result. Full cost includes AI credits plus human review and correction. An outcome counts only if it passes its acceptance rule without material correction and stays valid.

Cost per accepted outcome = total cost of all attempts ÷ number of accepted outcomes
OptionFull cost per attemptAcceptance rateCost per accepted outcome
Lightweight model$8.0040%$8.00 ÷ 0.40 = $20.00
Powerful model$14.0080%$14.00 ÷ 0.80 = $17.50

This is a decision framework, not a model ranking. Measure acceptance and full cost for each task category on your own work.

Multi-stage workflows compound: if every stage must succeed, end-to-end acceptance is the product of stage acceptance rates. Removing a redundant stage or making one retryable can save more than trimming tokens.

False-Economy Myths

MythReality
“Shorter prompts are always cheaper.”A too-short prompt often triggers costly follow-ups. Scope and clarity matter more than length.
“Never start a new session.”Start fresh for an unrelated problem or a new phase; avoid restarting the same active task.
“Cheaper models are always the safe default.”A wrong answer from an under-powered model often costs more in total than one correct answer.
“Completions and chat cost the same.”Completions and next edit suggestions don't consume AI credits; chat, agent, CLI, and cloud agent usage does.
“Cached input is always exactly 10x cheaper.”Typically about 10% of input, but it varies by model. Check the pricing row.

Key takeaway

Let Fusion or Auto handle the default choice, override it only with evidence, and judge every choice by cost per completed, verified task.
