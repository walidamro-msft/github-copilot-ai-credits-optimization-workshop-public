Measure and Improve

Every optimization is a hypothesis. Measure it on a fixed task set, change one variable at a time, and keep only what improves cost per accepted outcome.

The Before/After Loop

flowchart LR
    F[Freeze 5 to 10 tasks] --> H[Hold all else constant]
    H --> B[Run before arm]
    B --> C[Change one variable]
    C --> A[Run after arm]
    A --> D{Better per accepted outcome?}
    D -->|Yes| K[Keep]
    D -->|No| R[Revert or retest]
    class F,H neutral
    class B,A azure
    class C warning
    class D neutral
    class K success
    class R danger
  1. Freeze the task set: pick 5–10 representative tasks and write a one-line acceptance rule for each before running anything.
  2. Hold everything constant: same model, tools, instructions, and session strategy, except the one variable you test.
  3. Run the before arm and record every task.
  4. Change exactly one thing and run the same tasks as the after arm. Run each task more than once if you can, because output is non-deterministic.
  5. Compare and decide on cost per accepted outcome, not credits per attempt.

Record per task, per arm

FieldWhy
AI creditsThe spend side of the comparison
Context tokensShows whether the change reduced carried context or only moved it
Pass or fail against the acceptance ruleKeeps “cheaper but worse” from looking like a win
Rework turnsThe cost that cheap-looking options hide

Key takeaway

Adopt a change only when cost per accepted outcome improves and acceptance doesn't drop. A cheaper arm with lower acceptance is a regression. Five to ten tasks give a directional answer for a habit decision, not an organization-wide statistic.

Make It Stick: A 30-Day Habit Plan

Small, consistent changes outperform an ambitious plan nobody follows. Pick three habits, name when you apply each one, and decide how you will know in 30 days whether it worked.
