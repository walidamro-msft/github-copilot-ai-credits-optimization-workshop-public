Detailed Training Guide

Module-by-module talk track, discussion prompts, and lab facilitation notes, adapted from the Module 2 Developer Efficiency workshop guide.

Trainer-onlyFacilitation guide

Opening: Overview and AI Credits

  • Anchor idea: request count no longer explains cost. Two identical-looking requests can differ by 10x depending on context, model, cache state, and output.
  • Walk through the worked example on the AI Credits Fundamentals page: cached input versus cold cache, and output costing more than all cached input.
  • One-minute check: ask attendees to classify completions, a chat question about a failing test, a next edit suggestion, a Copilot CLI prompt, and a Spark request as billed or unbilled. Answer: completions and next edit suggestions are unbilled; the rest are billed.
  • Discussion: which token category do attendees suspect dominates their own sessions?

Choosing the Right Interface

  • Misconception to address: “Chat or agent for everything”. Agents spend turns deciding a small edit doesn't need exploration.
  • Use the decision tree; ask the room to place two of their own recent tasks on it.
  • Discussion: what would make “smallest sufficient interface” a team habit rather than an afterthought?

Context, Customizations, and Memory

  • Lead with the always-on versus on-demand table. The recurring cost is instructions and tool schemas, not the number of customizations.
  • Stress that the goal is the smallest sufficient prompt, not the shortest. Show the before and after T1 prompt.
  • Memory: emphasize review triggers (convention change, archived project, stale advice) and never storing secrets or one-time task detail.
  • Discussion: does your team's instructions file read as specific and grounded, or generic? Where does the team skip tests or linters in a way that likely causes rework?

Sessions, Caching, and Session Limits

  • Explain cache invalidation in one sentence: anything that changes the request prefix (model, reasoning, tools) or lets it expire forces the full context to be billed fresh.
  • Avoid two opposite myths: “never start a new session” and “restart constantly”. Restart when the problem or phase changes; compact when the task stays relevant.
  • Session limits: call out the documentation conflict on scope and the 30-credit minimum. Ask attendees to report what their CLI version shows in Lab 03.
  • Discussion: which of the six handoff fields does your team most often lose between sessions, days, or people?

Model Strategy and Measurement

  • Lead with Copilot Fusion as the default where available, Auto elsewhere. State discounts with their date and source.
  • Work the full-cost example: the powerful model wins per accepted outcome despite costing more per attempt.
  • Close with the before/after loop and the habit plan. Ask each attendee to name one habit they will use in their next session.
  • Discussion: which optimization on your team is believed rather than measured, and what fixed task set would settle it?

Lab Facilitation

  • Before: confirm Copilot CLI is allowed by policy and attendees are on VS Code 1.120+ and Copilot CLI 1.0.48+. Have the repository URL ready.
  • Lab 01: the most common blocker is Python not on PATH; suggest python3 or py. Remind attendees that a failed baseline attempt is valid data.
  • Lab 02: check that attendees configure tools before the first prompt of the test session.
  • Lab 03: if an agent can't edit files, the model likely needs apply_patch or edit in --available-tools. If a limit triggers, use it as a teaching moment.
  • Lab 04: if the subagent row is missing from /usage, the session model is Auto. Restart with --model.
  • Stretch: attendees who finish early can run T4 on both arms, or compare Fusion Standard with Fusion High on T1.

Backup Plan

  1. If live CLI or chat is unavailable, walk through the comparison tables as a discussion.
  2. Switch attendees to the supplied prompts, inventories, and before/after dataset in the Module 2 lab guide.
  3. Screen-share the official documentation pages linked on each topic instead of the live product.
  4. Keep the results worksheet and habit plan as the artifacts attendees leave with.
