Lab 04: Model Strategy and Evaluation

Settle a model question with evidence: run the same tasks on two arms, compare cost per accepted outcome, and try a cheaper subagent for bounded work.

VS Code + Copilot CLIL400~35 min

Scenario and Objectives

Your team debates whether a lightweight model is “good enough” for routine tasks. Instead of arguing, you'll run a small before/after evaluation and let cost per accepted outcome decide.

  • Run three fixed tasks on two arms that differ only by model.
  • Compute cost per accepted outcome and decide whether to keep, revert, or retest.
  • Delegate a bounded task to a custom agent running on a cheaper model in Copilot CLI.
  • Get personalized cost tips and write a 30-day habit plan.
Related topics: Model Strategy · Measure and Improve

Build

Step 1: Freeze the experiment

  1. Open tasks/task-set.md and reread the acceptance rules for T2, T3, and T5. Don't change them after you start.
  2. Choose the Arm B model. Hover models in the VS Code model picker to see their cost tier, and pick one marked Low. Write both arms in the worksheet.
  3. Confirm the tool set from Lab 02 and default reasoning. These stay the same for both arms.

Step 2: Run Arm A in VS Code

Repeat for each task:

  1. Start a new agent session and select the Arm A model.
  2. Paste the refined prompt for the task from tasks/task-set.md.
  3. Check the acceptance rule. For T2 and T3, run python -m unittest; for T3, also confirm the new test fails if you temporarily remove the check in release_stock, then restore it.
  4. Record credits (sum of per-turn hovers), pass or fail, and rework turns. If you needed a follow-up prompt to pass, count its credits and mark one rework turn.
  5. Save the attempt: git stash push -u -m "A-T2" (use the task ID). T5 changes no files, so there is nothing to stash.

Step 3: Run Arm B in VS Code

  1. Repeat Step 2 for each task with the Arm B model, using stash labels B-T2 and B-T3.

Step 4: Compute cost per accepted outcome

  1. For each arm, add up the credits for all attempts, including rework.
  2. Count accepted tasks: a task counts only if it met its acceptance rule.
  3. Divide total credits by accepted tasks and fill in the comparison table in the worksheet.
Credits per accepted task = total credits for the arm ÷ accepted tasks
How to read the result
  • Adopt Arm B for these task types only if its credits per accepted task are lower and it accepted as many tasks as Arm A.
  • If Arm B is cheaper per attempt but failed a task, it is a regression for that task type, not a saving.
  • Three tasks run once give a directional answer. Mark the decision “retest” if the arms are close, and rerun each task more than once.

Step 5: Delegate a bounded task to a cheaper subagent

  1. Create .github/agents/test-writer.agent.md. Replace <lightweight-model-id> with a lightweight model ID listed by /model in Copilot CLI, such as claude-haiku-4.5.
.github/agents/test-writer.agent.md 
---
name: test-writer
description: Writes focused unittest tests for the orders package. Use only for adding tests.
model: <lightweight-model-id>
tools: ["view", "glob", "grep", "edit", "create", "apply_patch"]
include-custom-instructions: true
---
Add only the requested unittest tests under tests/. Never change production code. Reply with the diff only.
  1. Start Copilot CLI with a specific session model, not Auto, so the subagent can use its own model. Replace <session-model-id> with a versatile model from /model: 
    copilot --model <session-model-id>
  2. Send: Use the test-writer agent to complete task T3 in tasks/task-set.md. Stop when the test is added.
  3. Run !python -m unittest to verify without spending credits.
  4. Run /usage. Confirm you see a row for the session model and a separate row for the subagent's model, each with its own credits.
  5. Exit, then save the attempt with git stash push -u -m "lab04-subagent".
Important: if the session model is Auto, subagents inherit the resolved session model and ignore their own model field, so you won't see a separate model row.

Step 6: Get cost tips and plan your habits

  1. In Copilot CLI, run /chronicle cost-tips. In VS Code chat, the equivalent is /chronicle:cost-tips. This request consumes credits.
  2. Compare the tips with your worksheet. Which tip matches what you measured?
  3. Fill in the 30-day habit plan in the worksheet with three habits, when you apply each, and how you will know in 30 days whether it worked.

Test and Verify

git stash list
git status --short
  • The worksheet has Arm A and Arm B rows for each task, with credits, pass or fail, and rework turns.
  • The cost-per-accepted-outcome table is filled in and the decision is keep, revert, or retest.
  • /usage in Step 5 showed separate rows for the session model and the subagent model.
  • Your 30-day habit plan lists three habits with a way to measure each.
  • git status is clean at the lean configuration commit.

Troubleshooting

SymptomCheck
The custom agent doesn't appearConfirm the file is in .github/agents/ and has a description; run /agent to list agents.
The subagent uses the session modelThe session model is probably Auto; restart with --model set to a specific model.
The model ID is rejectedYour plan or policy may not allow it. Pick another ID listed by /model.
The arms are too close to callRecord “retest” and rerun each task two or three times; output is non-deterministic.

Cleanup and References

Keep your worksheet. You can delete ~/credit-lab when you no longer need it; drop stashes with git stash clear inside it first if you want to keep the folder. No cloud resources were created; the only cost was the AI credits for each run.
