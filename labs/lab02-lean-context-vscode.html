Lab 02: Lean Context, Instructions, and Tools

Cut the context that rides along on every turn without losing anything the agent needs, then prove it with the same task you ran in Lab 01.

VS CodeL400~35 min

Scenario and Objectives

The project's instructions file has grown into a mix of generic advice, procedures, and sprint notes, and generated logs pollute every search. You'll restructure the customizations so only durable rules are always on, and rerun task T1 with a scoped prompt.

  • Measure how much of the context window the instructions file uses.
  • Rewrite .github/copilot-instructions.md to essentials and move detail into a path-specific instruction, a prompt file, and a skill.
  • Exclude noisy files from agent search and prune the tool set.
  • Review your Copilot Memory settings.
  • Rerun T1 with a task, context, and stop condition, and compare with your baseline.
Related topics: Context and Prompt Efficiency · Always-On vs. On-Demand Customizations · Copilot Memory Hygiene

Only the lean instructions stay always on. Green customizations load only when they apply; gray content is deleted because it never belonged in instructions.

Build

Step 1: Measure the instructions' weight

  1. Open ~/credit-lab in VS Code and open .github/copilot-instructions.md. Read it and mark each section as keep, move, or delete.
  2. Start a new agent session with your Lab 01 model, and send the T5 prompt from tasks/task-set.md. It explains code and edits nothing.
  3. Hover over the context window control and record the total context and the instructions share in the worksheet notes.

Step 2: Rewrite the always-on instructions

  1. Replace the contents of .github/copilot-instructions.md with only the durable, project-specific rules: test command, money handling, known pitfalls, and output expectations.
  2. Keep it to one screen.
Show a lean instructions file 
# Orders project

- Python 3.10+, standard library only. Run tests with `python -m unittest` from the repo root. Don't add pytest or other packages.
- Money is always `decimal.Decimal`, never `float`. Round to cents with `ROUND_HALF_UP` only at the end of a calculation.
- Don't change a test to make it pass unless the task says the test is wrong.
- Keep changes minimal and limited to the files named in the task.
- Reply with a diff or the changed lines, not whole files. Don't suggest extra improvements.

Step 3: Move detail into on-demand customizations

  1. Create .github/instructions/reports.instructions.md with the report formatting rules, scoped to orders/report.py.
  2. Create .github/prompts/release-checklist.prompt.md with the release checklist.
  3. Create .github/skills/publish-docs/SKILL.md with the documentation publishing procedure.
  4. Delete the sprint notes. Ticket numbers, demo plans, and temporary branch names are prompt content, not durable instructions.
.github/instructions/reports.instructions.md 
---
applyTo: "orders/report.py"
---
- Text reports: id 8 characters left-aligned, customer 20 left-aligned, total 10 right-aligned. Last line is the grand total labeled `TOTAL`.
- JSON reports: keys `orders` and `grand_total`. Serialize `Decimal` values as strings with two decimals, never floats.
.github/prompts/release-checklist.prompt.md 
---
description: Walk through the release checklist for the orders package
---
1. Update the version in `orders/__init__.py`.
2. Run `python -m unittest`; stop if anything fails.
3. Add a `CHANGELOG.md` section for the version with Added, Changed, and Fixed.
4. Draft release notes from that section.
.github/skills/publish-docs/SKILL.md 
---
name: publish-docs
description: Generate and publish the API documentation for the orders package. Use when asked to build or publish docs.
---
1. Check every public function has a docstring with Args, Returns, and Raises.
2. Build the HTML documentation into `site/`.
3. Review the generated pages for broken links before publishing.

Step 4: Exclude noisy files

  1. Generate the noise: run python tools/make_noise.py. It writes about 2 MB of logs to logs/.
  2. Add logs/ to .gitignore.
  3. Create .vscode/settings.json to keep logs visible in the Explorer but out of agent search:
.vscode/settings.json 
{
  "search.exclude": {
    "logs/**": true
  }
}

The logs mention order_total and discount thousands of times. Without exclusions, every agent search for those terms returns log snippets that count toward the context window.

Step 5: Prune the tool set

  1. Start a new agent session. Before you type anything, select Configure Tools in the chat input.
  2. Keep the built-in tools for reading, searching, editing files, and running terminal commands.
  3. Clear MCP servers and tool sets this task doesn't need, such as browser automation or GitHub issue tools.
Important: configure tools before the first prompt. Changing enabled tools mid-session invalidates the prompt cache.

Step 6: Review Copilot Memory

  1. In VS Code, open Settings and search for memory. Note whether Copilot Memory is enabled; it is off by default in VS Code.
  2. If your plan allows it, open https://github.com/settings/copilot/memory and review any stored preferences. Delete anything stale, task-specific, or sensitive.

Step 7: Commit the lean configuration

git add .
git commit -m "lean context configuration"

Labs 03 and 04 start from this commit.

Test and Verify

  1. In the session where you configured tools in Step 5, send the refined T1 prompt from tasks/task-set.md.
  2. Record credits per turn, session context, pass or fail, and rework turns in a new Lab 02 row.
  3. Run the tests, then save the attempt with git stash push -u -m "lab02-vscode".
python -m unittest
  • All 8 tests pass and only orders/pricing.py changed.
  • The instructions share of the context window is visibly smaller than in Step 1.
  • Your Lab 02 row shows fewer rework turns or fewer credits than the Lab 01 VS Code row, or you can explain why not.
  • git log --oneline shows the lean context configuration commit.

Troubleshooting

SymptomCheck
The path-specific instruction doesn't applyConfirm the file name ends in .instructions.md and the applyTo glob matches orders/report.py.
The prompt file doesn't appear in chatConfirm it is in .github/prompts/ and ends in .prompt.md; type / in chat to list prompt files.
Search still returns log linesCheck the search.exclude glob and that .vscode/settings.json is in the workspace root.
Results are worse than the baselineCheck that you didn't remove the test command or the Decimal rule. Leaner is only better if the needed context remains.
