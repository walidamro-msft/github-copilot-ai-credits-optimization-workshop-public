Lab 03: Sessions and Spend Control

Run a multi-step feature in Copilot CLI the cache-aware way: narrow scope, a spending cap, plan and implement in separate sessions, and compaction when the thread grows.

Copilot CLIL400~30 min

Scenario and Objectives

Your team needs JSON output for order summaries (task T4). It touches code, tests, and a formatting decision, so it is a good candidate for research, plan, then implement, with a cap on what any one session can spend.

  • Start Copilot CLI with only the tools the task needs and compare /context with Lab 01.
  • Set an AI credit session limit and observe how it behaves.
  • Plan in one session, write a six-field handoff, and implement in a fresh session.
  • Compact a growing thread with a focus and inspect the checkpoint.
  • Run a capped, non-interactive prompt.
Related topics: Sessions, Caching, and Compaction · AI Credit Session Limits · Always-On vs. On-Demand Customizations

Architecture

flowchart LR
    S1[Plan session] -->|handoff| S2[Implement session]
    S2 -->|compact| S2C[Compacted thread]
    S2C --> CP[(Checkpoint)]
    L[Session limit] -.->|caps| S1
    L -.->|caps| S2
    P[Prompt-mode run] -->|max-ai-credits| OUT[One answer]
    class S1 accent
    class S2,S2C azure
    class CP data
    class L danger
    class P neutral
    class OUT success

Planning and implementation run in separate sessions joined by a short handoff. A session limit caps each interactive session, and the prompt-mode run has its own cap.

Build

Step 1: Start with a narrow tool set

  1. From ~/credit-lab, start Copilot CLI with only file, search, and shell tools, and without the built-in MCP servers. Use the shell tool name for your platform.
PowerShell 
copilot -n t4-plan --available-tools "view,glob,grep,edit,create,apply_patch,powershell" --disable-builtin-mcps
bash 
copilot -n t4-plan --available-tools "view,glob,grep,edit,create,apply_patch,bash" --disable-builtin-mcps
  1. Run /model and choose the same option as in earlier labs.
  2. Run /cwd and confirm the working directory is ~/credit-lab.
  3. Run /context. Compare System Tools, MCP Tools, and Custom Instructions with your Lab 01 CLI row.

Expected result: MCP Tools is zero or near zero, and Custom Instructions is smaller because of your Lab 02 changes.

Step 2: Set a session limit

  1. Run /limits set max-ai-credits 30.
  2. Run /limits to open the dialog and note how your CLI version describes the limit's scope: the whole session, or each response.
Note: GitHub's how-to page and the CLI command reference describe the scope differently. Record what your version shows. If a task reaches the limit, the agent stops cleanly and asks you to reset or raise it; raise it with /limits set max-ai-credits 60.

Step 3: Plan without implementing

  1. Send: 
    /plan Add JSON output to format_summary as described in task T4 in tasks/task-set.md. Plan only; list files, the function signature, the JSON shape, and the tests to add.
  2. Review the plan. Ask for corrections if it changes text output or uses floats for money. Don't approve implementation.
  3. Send: 
    Draft a clean-session handoff for implementing this plan with six fields: task and outcome, current state, important files, decisions, constraints, next action and stop condition. Keep it under 20 lines. Don't write files.
  4. Copy the handoff into the handoff section of ~/credit-lab-results.md. Edit anything that is wrong or too long.
  5. Run /usage and note the credits used for planning.

Step 4: Implement in a fresh session

  1. Run /new, then /rename t4-implement. If the prompt still shows plan mode, press Shift+Tab until it returns to standard mode.
  2. Run /limits and confirm the limit is still set; set it again with /limits set max-ai-credits 30 if needed.
  3. Paste your handoff as the first message, followed by: Implement this now. Stop when python -m unittest passes. Reply with the diff only.
  4. Verify without spending credits by running the tests through the shell escape, which bypasses Copilot: 
    !python -m unittest

Step 5: Grow the thread, then compact it

  1. Send: Add one unittest for format_summary with an empty orders list in JSON mode. Diff only.
  2. Run /context and record the Messages tokens.
  3. Run /compact focus on the JSON format decisions in orders/report.py.
  4. Run /context again and compare Messages.
  5. Run /session checkpoints, then /session checkpoints 1, and check whether the summary kept the decision to serialize money as two-decimal strings.

Step 6: Record and exit

  1. Run /usage and record the implementation session's credits in a Lab 03 row, together with the planning credits from Step 3.
  2. Run /exit.

Step 7: Run a capped non-interactive prompt

  1. Run the T5 explanation with read-only tools and a cap:
copilot -p "Explain in at most 5 bullets how order_total in orders/pricing.py computes a total, including the order of discount and tax. Do not edit any files." --max-ai-credits 30 --available-tools "view,glob,grep"

Expected result: a short answer followed by usage statistics, and no file changes. Copilot Memory is off in prompt mode unless you add --enable-memory.

Test and Verify

python -m unittest
git status --short
  • All tests pass, including the new JSON tests.
  • git status shows changes only in orders/report.py and tests/test_report.py.
  • The worksheet has a six-field handoff of about one screen or less.
  • Messages tokens dropped after /compact, and the checkpoint kept the money-format decision.
  • You recorded how your CLI version scopes the session limit.

Save the attempt: git stash push -u -m "lab03-cli".

Troubleshooting

SymptomCheck
The agent says it can't edit filesYour model may use apply_patch or edit; confirm both are in --available-tools, and that you left plan mode.
The agent can't run testsInclude powershell on Windows or bash on macOS and Linux in --available-tools.
/limits set rejects the valueThe minimum is 30 AI credits.
The limit stops the task mid-implementationReview progress, then raise the limit with /limits set max-ai-credits 60 or tighten the prompt and start fresh.
The checkpoint lost a decisionThat is the compaction tradeoff. Restate the decision, or compact with a more specific focus next time.
